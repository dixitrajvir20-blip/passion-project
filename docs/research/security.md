# Security risk register research — Astro 7 + Preact static site on GitHub Pages (17 Sep 2026)

All claims tagged [Sn] → source list at the end. A few items are flagged **UNVERIFIED**.

## Key findings that shape everything
1. **GitHub Pages cannot set HTTP headers** (CSP, HSTS, Permissions-Policy, X-Frame-Options, COOP). GitHub staff: "a `meta` tag unfortunately is the only way" (May 2023); thread still open in 2026 [S1]. Pages docs say sites "should not handle sensitive transactions like passwords" [S2]. A `<meta http-equiv="Content-Security-Policy">` works for most directives but **cannot** deliver `frame-ancestors`, `sandbox`, `report-to/report-uri` [S3]; meta-based X-Frame-Options does not work [S4]. Free hosts that set headers: Cloudflare Pages `_headers` [S5][S6], Netlify [S7], Vercel [S8], or Cloudflare Transform Rules in front of Pages [S9].
2. **Astro CSP is stable** since Astro 6 (10 Mar 2026) as `security: { csp: true }`; static output emits a `<meta http-equiv="content-security-policy">` with SHA-256 hashes of every inline script/style. Limits: external scripts/styles must be declared, `<ClientRouter/>` and Shiki unsupported, off in dev [S10][S11].
3. **Email is not a real authentication factor**: NIST SP 800-63B-4 (final 1 Aug 2025): "Email SHALL NOT be used for out-of-band authentication" [S13][S14]; ASVS 5.0 (30 May 2025) 6.3.6 [S15][S16]. Magic links acceptable at low assurance; design passkeys as the primary factor.
4. **OWASP Top 10:2025 is final**: A01 Broken Access Control, A02 Security Misconfiguration, A03 Software Supply Chain Failures (new), A04 Cryptographic Failures, A05 Injection, A06 Insecure Design, A07 Authentication Failures, A08 Software or Data Integrity Failures, A09 Security Logging & Alerting Failures, A10 Mishandling of Exceptional Conditions (new) [S17].
5. **2025 npm incidents**: chalk/debug (8 Sep 2025, maintainer socially engineered, 24+ packages, browser crypto-clipper) [S18]; Shai-Hulud (Sep 2025, postinstall worm stealing npm/GitHub/cloud creds; "2.0" Nov 2025 moved to preinstall, ~350 users/25k+ malicious repos) [S19]; Nx "s1ngularity" (26 Aug 2025: `pull_request_target` PR-title injection; postinstall used local AI CLIs to hunt secrets) [S20]. Responses: npm classic tokens revoked 9 Dec 2025, granular write tokens max 90 days, 2FA enforced on publish, OIDC trusted publishing [S21][S22][S23].

## Recommended headers (OWASP HTTP Headers Cheat Sheet [S73]; ASVS V3.4 [S15])
```
Content-Security-Policy: default-src 'self'; script-src 'self' 'sha256-…'; style-src 'self' 'sha256-…';
  img-src 'self' data: https:; font-src 'self'; connect-src 'self' https://<auth-api>;
  frame-src https://www.youtube-nocookie.com; object-src 'none'; base-uri 'none';
  form-action 'self'; frame-ancestors 'none'; upgrade-insecure-requests
Strict-Transport-Security: max-age=63072000; includeSubDomains; preload
X-Content-Type-Options: nosniff
X-Frame-Options: DENY
Referrer-Policy: strict-origin-when-cross-origin
Permissions-Policy: geolocation=(), camera=(), microphone=(), payment=(), usb=(), interest-cohort=()
Cross-Origin-Opener-Policy: same-origin
Cross-Origin-Resource-Policy: same-site
X-XSS-Protection: 0
Cache-Control: no-store   (auth/API responses only)
```
Test with MDN HTTP Observatory [S74].

## GitHub Actions hardening checklist
Workflow-level `permissions: contents: read`; raise per job [S34]; pin every action to a SHA [S30]; SHA-pinning policy [S31]; no `pull_request_target`/`workflow_run` that checks out PR code [S32]; fork PRs require approval; `npm ci --ignore-scripts` + cooldown + `npm audit signatures` [S24][S28]; CodeQL default setup [S75]; Scorecard [S29]; ZAP baseline [S76]; Lighthouse CI [S77]; rulesets on `main` [S40]; 2FA with passkey/TOTP [S78]; environment protection on `github-pages`; OIDC trusted publishing if ever publishing a package [S23].

## Auth design recommendation (15–21-year-olds)
Keep the site static; a small separate auth origin so cookies are `__Host-` scoped. **Primary: passkeys** — synced passkeys on Android 9+, iOS 16+, macOS 13+, ChromeOS 129+; Windows sync "planned"; conditional UI everywhere; cross-device QR/hybrid [S79]; NIST permits syncable authenticators to AAL2 [S14]. **Fallback: email code/link** as low-assurance recovery: CSPRNG ≥128 bits, hashed, TTL 5–10 min (ASVS 6.5.5 caps at 10 min; Better Auth 300 s; Clerk 10 min; Supabase 1 h — shorten) [S15][S52][S53][S51]; single use; "Continue" button page (defeats Safe Links prefetch) or 6-digit code; same-browser binding; per-email 60 s cooldown; identical responses [S55]; never accept the email from the URL [S54]. **Sessions**: `__Host-sid`; regenerate on login; idle ~30 min, absolute ≤7 days; server-side logout [S15][S44]; CSRF via `Sec-Fetch-Site` + Origin [S58]. **No passwords** [S14]. **Minors**: email only; no public profile; India under-18 verifiable parental consent before DPDP Phase III (13 May 2027) [S60][S62].

Provider comparison (free tiers, Sep 2026): Supabase Auth — passkeys (primary flow) [S80], magic link 1 h default [S51], 50k MAU, pauses after 1 week idle [S81], Mumbai/Frankfurt regions [S82]; Better Auth (self-host on Workers/D1) — passkey plugin with conditional UI [S52b], magic link 5 min default [S52], Workers free 100k req/day, D1 5 GB [S83]; Clerk — passkeys paid only [S53], 50k MRU [S84]; Auth.js — passkeys experimental [S85]; Firebase — no native passkeys **UNVERIFIED**. Pick: Better Auth on Cloudflare Workers + D1 if comfortable running a tiny backend; otherwise Supabase (Mumbai or Frankfurt).
